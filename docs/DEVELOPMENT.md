# Разработка

## Структура

| Каталог | Содержимое |
| --- | --- |
| `App/` | SwiftUI-экраны, подключение к iPhone, pairing, каталог и Core Data |
| `Core/` | Модели SIM, фильтры, описания профилей, диагностика и возврат к стоку |
| `Resources/` | Метаданные каталога, настройки профилей, ассеты, модель Core Data и лицензии |
| `Tests/` | Проверки Swift и Python |
| `tools/` | Загрузка зависимостей, генерация ресурсов, сборка и проверка IPA |
| `vendor/ZIPFoundation/` | Исходники ZIPFoundation, используемые при сборке |

`project.yml` — источник конфигурации XcodeGen. Сгенерированные `App/Info.plist`, Xcode-проекты, бинарные зависимости, архивы сборок и локальные файлы pairing не хранятся в Git.

- CarrierSIM: MIT, [commit feb9e2f](https://github.com/ios-bundles/CarrierSIM/tree/feb9e2fd6887228ade281c4733866e98df416047), источник форматов событий CommCenter и сведений о применении профилей.

Минимальная версия устройства — iOS 26.0. Для Simulator в проекте задан минимум iOS 26.5 из-за готового среза idevice. Это не меняет минимальную версию IPA. Xcode 27 также экспортирует макрос `State`; alias `ViewState` явно выбирает property-wrapper API SwiftUI.

## Проверки

```sh
bash tools/test.sh
bash tools/bootstrap.sh
bash tools/test-pairing-ffi.sh
```

Основные тесты запускаются на macOS без Simulator: SIM и неоднозначные слоты, поиск и совместимость, настройки профилей, pairing и отмена, возврат к стоку, разбор диагностических событий, сохранение Core Data. FFI smoke test проверяет подготовку нативного pairing-хоста и метаданные Bonjour без сетевого сопряжения.

`tools/build.sh` собирает Release для физического iPhone, упаковывает IPA и вызывает `tools/verify_ipa.py`. Проверяются архитектура arm64, минимальная iOS, версии, иконка и необходимые ресурсы.

Сборка и эти тесты не заменяют проверку на iPhone. Для ручного теста нужны правильный и неправильный pairing, включённый и выключенный VPN, две SIM, обрыв соединения, уход в фон, перезагрузка и сверка активного профиля. Отдельно проверяются iOS 26 и iOS 27.

## Каталог

Метаданные соответствуют закреплённому архиву `catalog-ios27.2.1` исходного CarrierSelector. Архив загружается отдельно, его SHA-256 проверяется перед использованием. Пакеты Apple не включены в Git.

Для воспроизведения метаданных:

```sh
python3 tools/generate_resources.py /path/to/embedded_catalog-ios27.2.1.zip
```

`Resources/apn.json` — отдельный справочник, перенесённый из `APN_HELP_RU` закреплённой версии CarrierSelector. Он и лицензии хранятся в Git и не перезаписываются генератором. Лицензии CarrierSelector, idevice, ZIPFoundation и CarrierSIM находятся в `Resources/*-LICENSE.txt`.

Генератор читает `carrier.plist` и переопределения для платы. Словари объединяются рекурсивно, массивы заменяются. Отсутствующее значение остаётся неизвестным; системные значения по умолчанию, страновые настройки и поведение сети не моделируются.

`Resources/russia-research.json` хранит краткие описания, версии, ограничения и ссылки на источники. Новая версия профиля не наследует рекомендацию автоматически. Подборка исключает несовместимые параметры VoWiFi, фиксированный чужой ePDG и местный номер активации другой страны.

## Установка и сброс

Транспорт: LocalDevVPN → Remote Pairing → TLS-PSK → RSD → Lockdown / AFC / Installation Proxy. Native FFI вызывается на последовательной рабочей очереди. Параллельные установка, сброс и диагностика запрещены.

Обычная установка передаёт оригинальные файлы пакета Apple с `PackageType=CarrierBundle` в каталог, соответствующий выбранной SIM. До отправки сохраняется квитанция с хешами устройства и SIM. При неизвестном результате автоматического повтора нет.

Возврат к стоку воспроизводит механизм исходного CarrierSelector: в копии пакета штатного оператора очищается `SupportedSIMs`. Ожидается снятие пользовательской привязки с последующим отклонением изменённого пакета системой. После ручной перезагрузки приложение проверяет идентификатор активного штатного оператора, а не совпадение его версии с донором. Удаление привязки на файловой системе по журналу не подтверждается.

Pairing хранится в Keychain с `WhenUnlockedThisDeviceOnly`. Временная копия защищена Data Protection и удаляется после соединения. Создание pairing на iOS 27 требует подтверждения PIN в системных настройках. Для iOS 26 предусмотрен импорт Remote Pairing с компьютера.

## Диагностика

`LiveNetworkModel` читает `serviceCurrentRadioAccessTechnology` и `dataServiceIdentifier` из CoreTelephony, а также маршрут NWPathMonitor. Обновление работает только при открытом экране в активном приложении. Идентификаторы CoreTelephony не сопоставляются со слотами Lockdown по порядку или по суффиксу. Сетевой маршрут с VPN не используется как доказательство доступности интернета или регистрации IMS.

`DirectTelephonyModel` запускает собственный Objective-C адаптер `CSTelephonyProbe` без pairing и VPN. `CoreTelephonyClient` и `CTXPCServiceSubscriptionContext` разрешаются во время исполнения. Перед каждым вызовом проверяются наличие селектора, число и типы аргументов, тип и размер результата; Objective-C исключения превращаются в статус недоступности. Слоты 1/2 запрашиваются явно через `contextWithSlot:`, без привязки к непрозрачным идентификаторам публичного API. На устройстве с одной линией запрос второго слота может вернуть ошибку.

| Запрос | Что показывается |
| --- | --- |
| `getIMSRegistrationStatus:error:` | Только возвращённые BOOL `isRegisteredForVoice` и `isRegisteredForSMS` |
| `getActiveConnections:error:` | Наличие `kCTDataConnectionServiceTypeIMS`, отдельно от регистрации голоса/SMS |
| `getDataStatus:error:` | BOOL `attached`, `newRadioSaDataBearer`, `newRadioNsaDataBearer` |

Сигнатуры исследованы по опубликованным [интерфейсам CellularInfo](https://github.com/DevelopCubeLab/CellularInfo/blob/main/CellularInfo/Head/CoreTelephonyClient.h). В этом проекте «базовый IMS без дополнительных прав» определяется через список соединений. Поэтому наш экран не трактует его как подтверждение SIP-регистрации, VoLTE или VoWiFi. Адаптер реализован самостоятельно; исходные заголовки и контроллеры CellularInfo не включены в приложение. Дополнительные entitlements не запрашиваются. На физическом iPhone с iOS 27.2.1 подтверждено чтение соединения IMS и attached. Регистрация голоса/SMS и дополнительные запросы сигнала получили NSPOSIXErrorDomain/EPERM. Эти результаты не распространяются автоматически на другие устройства или версии iOS.

Прямые запросы выполняются последовательно вне главного потока, с промежуточной выдачей результатов. Через 12 секунд ожидание в интерфейсе заканчивается, уже полученные поля остаются видимыми, следующие запросы отменяются. Текущий синхронный вызов ОС нельзя прервать: пока он не вернулся, новые запросы не запускаются. Поздние ответы после тайм-аута или ухода с экрана игнорируются. Автообновление каждые 15 секунд работает только на видимом активном экране и прекращается после тайм-аута до ручной повторной проверки.

Ошибки сохраняют числовой код и разрешённое имя домена, без `localizedDescription`, `userInfo` и сырых объектов. Числовой код сам по себе не объявляется отказом в правах. Отчёт включает булевы состояния услуг, ошибки прямых запросов и счётчики журнала. Модульные тесты исполняют адаптер с подставными Objective-C объектами: проверяются ABI, исключения, пустые ответы, ошибки с непустым результатом, отмена и исключение личных данных. Отдельно проверяются тайм-аут и поздняя доставка на уровне модели; это не заменяет тест на iPhone.

Отдельное соединение читает `os_trace_relay`. После открытия потока запускается ограничение в 90 секунд. При обрыве после первого успешного подключения разрешено до трёх попыток переподключения в пределах общего времени. Новые попытки для одного обрыва прекращаются через 20 секунд; уже выполняющийся нативный вызов может завершиться позже. После переподключения сбрасывается только незавершённый SIP-буфер, счётчики и значения сохраняются. Начальная ошибка подключения не запускает повторов. Отмена закрывает транспорт этой сессии; освобождение ресурсов синхронизировано с закрытием. На этапе первоначального подключения отмена ждёт завершения нативного вызова.

Счётчики различают все события, события CommCenter, редактированные системой значения и распознанные показатели. События больше не отбрасываются из-за небольшого расхождения часов; исходное время показывается явно, а некорректная дата помечается временем получения.

Парсер сохраняет только разрешённые значения: IMS, RAT, RSRP/SINR, флаги услуг, ePDG, состояния IKE и ограниченные метаданные SIP/SDP. Сырые строки, SIP-адреса и идентификаторы абонентов не записываются. Неизвестные поля не трактуются как отрицательный результат. Флаги услуг и RSRP/SINR извлекаются независимо: скрытое соседнее значение не отбрасывает открытые данные. Для известных полей отдельно учитываются упоминания, скрытые значения и успешный разбор; общий счётчик `<private>` не приписывается конкретному полю. Только сеть и роуминг не считаются результатом диагностики IMS/сигнала. При конфликте меток слот остаётся неопределённым.

Сведения о кодеке берутся только из завершённого успешного SIP-ответа INVITE/PRACK/UPDATE с однозначным речевым кодеком. Это не подтверждение прохождения аудио; ответ может содержать новое предложение параметров. Недокументированные форматы событий отличаются между версиями iOS, поэтому отсутствие показаний не означает отсутствие услуги.

Режим «Регистрация» предлагает пользователю вручную переподключить сотовую сеть, оставив Wi-Fi включённым; приложение не меняет авиарежим или настройки SIM. Режим «Звонок» собирает события во время обычного вызова. Публичные поля журнала зависят от версии iOS: приложение не восстанавливает содержимое `<private>`. [Apple описывает настройку журналирования на iOS через диагностические профили](https://developer.apple.com/forums/thread/702941); такие профили приложение не устанавливает.

## Интерфейс и Apple HIG

- [Color](https://developer.apple.com/design/human-interface-guidelines/color): системные grouped-фоны, семантические цвета текста и синий акцент для действий. Цвета адаптируются к светлой/тёмной теме и повышенному контрасту.
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout): подключение и SIM выше технических подробностей; дополнительные настройки раскрываются по запросу. Убраны повторные заголовки главной и каталога.
- [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): стандартные bordered/borderedProminent кнопки с системными состояниями.
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility): семантические размеры текста, вертикальная компоновка значений при accessibility-размерах, текстовые обозначения статусов вместе с иконками.

Для визуальной приёмки нужны iPhone/Simulator: светлая и тёмная темы, Increase Contrast, максимальный Dynamic Type, портретная и альбомная ориентация, возврат из вложенных экранов к главной. Проверка сборки не заменяет эту приёмку.


### Сценарий установки

Три вкладки: «Установка», «Профили», «Помощь». `InstallationScreen` управляет выбором SIM, подготовкой и подтверждением отправки. `AppModel.selectedProfile` хранит текущий выбор; карточка в каталоге возвращает на экран установки. Кнопки отправки и проверки закреплены в safe area, доступность сопровождается причиной блокировки. Настройки подключения открываются отдельным листом, технический отчёт — из помощи.

`InstallReceipt` сохраняет незавершённую операцию после перезапуска приложения. Обычное обновление данных больше не снимает блокировку: для обеих операций нужна явная проверка после подтверждения ручной перезагрузки. Автоматически установить факт перезагрузки приложение не может. Затем сравниваются хеш устройства, хеш SIM, идентификатор пакета и версия (для сброса — действительная версия штатного оператора). При чтении незавершённой операции выбирается соответствующая ей SIM. Отдельное состояние успеха не смешивается с завершением загрузки каталога.

Автотесты проверяют, что обновление без подтверждения, другой iPhone, другая SIM и чужой активный пакет не закрывают установку.


Подтверждения установки, перезагрузки, сброса и удаления pairing используют системный `alert` с явной отменой. Они не привязываются стрелкой к геометрии списка или закреплённой панели, как прежние `confirmationDialog`. Формы подключения и выбора файлов остаются системными sheet/importer.


### Сравнение, выбор и загрузка

`ProfileComparison` ищет точный идентификатор и версию активного пакета, выбирая совместимые записи с наибольшим приоритетом платы. Настройки берутся из метаданных каталога, а не из текущей памяти модема. Неизвестные значения и конфликтующие варианты не считаются ни выключенными, ни совпавшими. APN сравниваются как множества.

`InstallationDraftStore` хранит в UserDefaults путь, идентификатор и версию профиля, хеш устройства и хеш селектора SIM. Слот не используется для восстановления: смена слота допустима при той же SIM; смена SIM, устройства или версии пакета не приводит к автоматической подстановке. Отправка по-прежнему перепроверяет устройство и SIM через транспорт.

`ProfileVerification` используется и для результата на экране, и для снятия блокировки `InstallReceipt`. Другой iPhone, отсутствующая/неоднозначная SIM, нечитаемый пакет, отличающийся идентификатор и отличающаяся версия — отдельные результаты. Подтверждение ручной перезагрузки обязательно; при возврате к штатному пакету допускается версия, выбранная iOS.

`ConnectionFailure` использует числовые категории закреплённой idevice FFI ([lib.rs](https://github.com/jkcoxson/idevice/blob/8970209/idevice/src/lib.rs), [remote_pairing/errors.rs](https://github.com/jkcoxson/idevice/blob/8970209/idevice/src/remote_pairing/errors.rs)). Сырые сообщения FFI не показываются: в них могут быть пути с идентификаторами SIM. Общий socket/timeout не объявляется доказательством выключенного VPN. Повторное подключение только читает данные, не повторяет отправку.

`CatalogDownload` — отдельный URLSessionDownloadDelegate на каждую попытку, с последовательными callback. Показывает фактические байты и процент только при известном размере. Отмена выигрывает до начала проверки; после начала проверки кнопка отмены недоступна. Приложение не принимает HTTP-ошибку, отменённую попытку или пакет с неверным SHA-256; замена существующего архива выполняется через подготовленный файл. Поздние сообщения старой попытки отсекаются её идентификатором. Поддерживается продолжение, описанное ниже.

Тесты `WorkflowTests.swift` покрывают частичные и конфликтующие метаданные, точные версии, сохранение выбора и замену SIM, результаты проверки и классификацию ошибок. Для URLSession используется локальный HTTP-сервер на случайном loopback-порту: известный/неизвестный размер, 404, отклонение при проверке, отмена, повторная загрузка и отмена после начала проверки. Сервер завершается после теста.


### Каталог, история и дозагрузка

`ProfileCatalogLookup` используется для поиска активной версии, списка выпусков и сравнения двух выбранных пакетов. При сравнении без подключённого iPhone учитываются все варианты пакета; конфликтующие параметры остаются неоднозначными. Автоматический оператор берётся из однозначного штатного сопоставления SIM в `NativeCatalog`, с ограниченным списком известных идентификаторов. Установленный пакет-донор для определения оператора не используется. Неизвестные MVNO не подменяются основной сетью; ручной выбор имеет приоритет и сохраняется при обновлении.

Модель Core Data версии 1 (`Library.xcdatamodel`) сохранена без изменений. Версия 2 добавляет optional-поля `simKey`, `simLabel` и `contextData` в Operation; включена lightweight migration. `OperationContext` содержит хешированную пару устройства/SIM, маскированную подпись и версии исходного, целевого и прочитанного пакетов. Управляемые объекты остаются на main-queue viewContext. Фильтр SIM применяется к fetch до ограничения в 100 последних записей; старым событиям SIM не приписывается. SQLite-тест создаёт базу V1, открывает её через текущий LibraryStore и проверяет сохранность истории, избранного и новых групп после повторного открытия.

Дозагрузка следует [механизму URLSession](https://developer.apple.com/documentation/foundation/pausing-and-resuming-downloads): `cancel(byProducingResumeData:)`, `downloadTask(withResumeData:)` и данные возобновления из сетевой ошибки. Завершение отмены ждёт и delegate-callback, и callback с resumeData, независимо от их порядка. Оpaque-токен сохраняется до обновления UI, привязан к URL и SHA-256 закреплённого каталога, исключён из резервного копирования. Успех и невосстановимые попытки очищают токен. Проверяется полная собранная копия архива; частичная передача сама по себе не означает готовность пакетов.

Продолжение зависит от сервера и сохранности временного файла iOS. Если оно невозможно, доступна загрузка с начала. Локальные HTTP-тесты проверяют Range/206, реальный обрыв соединения с неполным Content-Length, успешное продолжение и возврат к полной загрузке при ответе 200 вместо диапазона. Визуальная проверка новых экранов на физическом iPhone ещё не выполнена.

## GitHub Actions и релизы

Workflow `.github/workflows/build.yml` запускает тесты, проверку pairing FFI и Release-сборку на `xcode-27` с Xcode 27.2. Он работает для push в `main`, pull request, тегов `v*` и ручного запуска. IPA и SHA-256 доступны в артефакте `CarrierSelector-unsigned`; логи сохраняются отдельно, в том числе при ошибках.

Для выпуска обновите `MARKETING_VERSION` и увеличьте `CURRENT_PROJECT_VERSION` в `project.yml`, добавьте `docs/releases/vX.Y.Z.md`, затем отправьте коммит и тег `vX.Y.Z`. Тег должен совпадать с версией внутри IPA. Только после успешной сборки job публикации создаёт GitHub Release с IPA и контрольной суммой. Права записи нужны только этой job; сертификаты и секреты подписи не используются. IPA нужно подписать перед установкой.

Публичная история начинается с версии 1.0.0. Предыдущая история разработки сохранена только в локальной резервной копии и не входит в новую ветку `main`.
